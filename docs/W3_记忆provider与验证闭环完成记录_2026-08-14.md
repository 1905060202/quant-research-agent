# W3 记忆 provider 定制 + 验证闭环 verifier 完成记录 · 2026-08-14

## 一、本周交付了什么

两个东西，一个结论先说：**记忆和验证全部落在 Hermes 既有扩展点上，核心循环一行没改。**

| 交付 | 路径 | 激活方式 | 作用 |
|---|---|---|---|
| qra_memory provider | `.hermes/plugins/qra_memory/` | `config.yaml` 里 `memory.provider: qra_memory` | 持久记忆层：去重、叙事链、契约、Dream 整合 |
| qra_verify 验证闭环 | `.hermes/plugins/qra_verify/` | `plugins.enabled` + pre_verify 钩子 | 声称-证据账本 + 回合末守卫 |

## 二、qra_memory：记忆怎么记、怎么查、怎么防膨胀

**协议（取 Mem0 增量思想，只 ADD 不 UPDATE）**：agent 每轮只往库里加新记忆，不覆盖旧记忆。防膨胀靠写入前三重对照：

1. **会话最近**：本会话刚记过的，直接拦（返回 `duplicate_of: session_recent`）
2. **库内精确**：内容一模一样，拦
3. **近似窗口**：trigram 候选窗内做相似度比较，≥0.85 拦

**三类改写都拦得住**（单元测试全过）：
- 字词微调："今日/今天"互换、多一个"了"
- 数字改写：`1341.99` 这个价格锚在，OR 探针必命中候选窗
- 纯中文中段改写：差异落在第 8 个字符、trigram 探针整窗落空时，退到二字前缀 LIKE 宽窗，靠比率门槛把关

**量化专用判重规则（e2e 逼出来的）**：`茅台今天收在 1341.99` 和 `2026-08-14 茅台收盘 1341.99 元` 文本相似度只有 0.5，常规门槛判不出是重复。但量化记忆里**数字是事实的身份**——同一个价格数字就是同一笔行情。规则：共享事实锚（小数价格/≥6 位长数字/英文词）时门槛放宽到 0.5。带连字符的日期 `2026-08-14` 会被切成短 token 不算锚，避免"同一天的两条不同事实"被误杀（单元反例已验证）。

**叙事链**：新记忆自动链接到同主题旧记忆（`linked_memory_ids`），detail 沿链 BFS 追 5 层。改写没被拦下时（比率 <0.5 的强改写），链还在——信息不丢、不散。

**契约记忆**：用户自己的文件（`§` 或逐行分隔）导入后 kind=contract，**只读**——expire 拒绝、dream 整合跳过、永不过期。权限分离：用户写的，agent 不能删。

**Dream 整合**：provider 内部守护线程（每日，interval 可用 env 覆盖），合并 ≥0.9 近似条目、清过期、归一化"昨天/今天/N天前"这类相对日期。注意：这是 provider 自己的线程，**绕开了 Hermes 的 cron 路径**——因为 cron agent 跑 `skip_memory=True`，记忆维护不能挂在那条线上。MemoryProvider 基类文档明确允许"may start background threads"，属于官方扩展点，不是黑魔法。

**诚实边界**：`sync_turn` 是记录在案的空操作。增量抽取协议里"每轮自动抽记忆"需要 LLM 抽取器，本版不做——provider 里塞 LLM 调用会把成本翻倍，且 Hermes 核心本来就会把工具调用结果喂回上下文。记忆工具是显式的：agent 觉得值得记，就调 `qra_memory_add`。这是范围决策，不是遗漏。

## 三、qra_verify：声称怎么被查、怎么被拦

**账本**：`qra_verify.db`，一笔声称一条记录（任务/声称内容/检查类型/状态/证据/时间戳）。

**四个确定性检查器**（零 LLM 成本）：
- `data_quote`：实时行情合理性（新浪源直连，价格>0 且字段齐）
- `file_exists`：文件存在
- `file_contains`：内容命中正则
- `numeric_in_range`：数值在区间

**回合末守卫（pre_verify 钩子）**：本回合改过文件（核心循环既有条件）→ 账本里 pending 的先补跑 → 还有 failed 的就返回 `{"action":"continue","message":...}` 强制模型再跑一轮。message 给三选一：修复复检 / 诚实撤回 / 标注不确定性。全部通过则不干预。防死循环双层：插件侧 attempt≥2 放弃，核心侧 max_verify_nudges 兜底。

**诚实原则**：失败不惩罚、只拦下。撤回（retract）是账本里的一等状态——"我说错了，撤"比"假装没说过"好。

## 四、四层验证证据

1. **单元（13/13，跑两遍）**：`/tmp/qra_w3_unit.py`——三种去重形态、价格锚改写、同日不同事实反例、链接桥、叙事链、契约导入/只读、expire、search 高亮、dream 整合。
2. **钩子直调（5 场景）**：force / retract-no-force / pending-auto-check / throttle（attempt≥2 放弃）/ session 隔离——直接调 `_pre_verify` 回调验证。
3. **e2e 真实会话**（`run_qra.sh -z`，state.db 消息流为证）：

```
133|tool|{"id": 1, "status": "failed", "evidence": "reports/e2e_w3.md 不存在"}
135|tool|{"bytes_written": 25, ...}          ← 写文件
136|assistant|步骤 1-5 已全部执行完毕...
138|tool|{"id": 1, "status": "passed", "evidence": "reports/e2e_w3.md 第 1 行命中 '2026-08-14'"}
139|assistant|复检通过。守卫已不再有 failed 声称拦截，收工。
```

   同一个会话里：改写记忆被判重（`duplicate_of=1`）、声称先 failed、写文件后**守卫强制续跑 1 次**、复检 passed 放行。agent 自己的最终报告确认"被守卫强制续跑了 1 次"。
4. **落盘核验**：`qra_memory.db` 1 条记忆（source=tool）；`qra_verify.db` 1 笔声称 passed、checked_at 比 created_at 晚 22 秒（两次独立检查）；state.db 会话 `agent_close` 干净退出。

## 五、三个坑（按踩中顺序）

1. **trigram 是连续三字符索引，二字共享搭不上桥**。`茅台今日` 和 `茅台价格` 共享"茅台"，但连续三字符零重叠——trigram MATCH 永远搜不到对方。修法：二字前缀 LIKE 宽窗兜底（比率门槛把关防误判）。这个限制要写进文档，不然下次还踩。
2. **`-z` 单发模式只回显最终答复**，中间回合不打印——e2e 证据不能只看终端输出，要去 state.db 的 messages 表翻消息流（守卫强制续跑的铁证在那里）。
3. **hermes CLI 顶层没有 `--session-id`**，`-z` 会话 id 自动生成；qra_verify 相对路径以 hermes 进程 cwd（项目根）为基准，不是 shell 会话目录——agent 第一次就把文件写到了 `~/reports/`。工具描述里已写明。
