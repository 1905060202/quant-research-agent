## 〇、一句话

**新 agent = Hermes 骨架（核心循环 + 持久记忆）+ 11 个 agent 的精华按六大能力维度逐一嫁接 + QRA 量化领域层。**

你要的四样东西各归其位：Hermes 持久记忆当骨架原样拿；prime 自我迭代做成最大的移植件；DSH 创新与 OpenHands 事件日志合成"事件溯源"层；Claude 专业化成记忆权限分离 + SKILL.md 契约。狩猎所得（Pi 的缓存纪律、smolagents 的代码块动作、Manus 的上下文策略、Letta 的分块记忆、Codex 的执行白名单）全部有明确落点。

## 一、铁律：为什么骨架不动，什么时候才动

v1-v7 五次推倒重来的死法只有一个：架构野心跑赢了验证。所以立这条铁律，全文所有设计服从它：

> **任何嫁接不得修改 Hermes 核心循环。需要改核心才能装下的创新，进入 C 类清单，凑够三条才触发深度重构——而且那时是带着 12 周实测数据重构，不是带着图纸重构。**

嫁接按落点分三级：
- **A 类**：落在 Hermes 现有插件面（memory provider / background_review / cron_providers / 工具注册 / SKILL.md），直接开工。
- **B 类**：现有插件面装不下，需要给核心周边打新扩展面（如 context-transformer 钩子、事件日志钩子）。中期立项，每个扩展面单独评审：优先绕（provider 面外挂弱形式），绕不过才打洞。
- **C 类**：必须改核心循环。禁止。凑三条 → 深度重构立项。

## 三、六大维度逐一设计

### 维度一：持久记忆（你要的"Hermes 记忆"再往上走一层）

**基底**：Hermes SQLite + FTS5 trigram CJK + provider 插件 + 字符预算 + 冻结快照。原样保留。

**增强（按优先级）**：
1. **Mem0 增量抽取协议**（A 类，改造既有插件）——写时增强：只 ADD 不覆盖；去重对照"本会话已抽 ≤20 + 库内相关记忆"；`linked_memory_ids` 把新旧记忆链成叙事链（持仓观点演化史、验证卡历史正是这个形状）；`expiration_date` 过期隐藏。工作量 2-4h。
2. **记忆权限分离**（A 类）——Claude Code 设计：用户写的契约（研报铁律/方法论）read_only 永不自动改；机器写的 auto-memory 单独管理。落点：记忆 provider 加 read_only 标志 + 写入路径拒绝。工作量 2-3h。
3. **Dream 式后台整合**（A 类）——复用 Hermes 现有 cron_providers：每 24h 去重、删陈旧、相对日期转绝对。工作量 2-3h。
4. **Letta 分块 + 自编辑**（B 类，v2.0）——记忆=上下文窗口的预留分块（label/描述/独立限额/read_only），agent 用工具自编辑记忆，系统提示内嵌记忆状态自省。Hermes 缺分块结构和自编辑工具，这是记忆维度的下一代形态。中期立项。
5. **CAMEL 评分截取**（C 类待观察，低优先）——按 token 预算给历史打分截取。先不做，若实测发现"读时选择"是瓶颈再提。

### 维度二：自我迭代（你要的"prime 自我迭代"）

**移植**：prime 双评审门（评审计划 + 评审执行）+ 回滚 + 并发拒绝 → 翻译成 Python 挂到 Hermes background_review。这是全项目最大单块（8-12h，W4）。移植要点：评审门要读"计划 vs 实际执行"的差异，不只是终稿检查。

**增强**：
- **Manus plan 复述机制**——todo.md 每步执行前复述目标，对抗长循环目标漂移。落点：评审门的第一步检查项（A 类，含在评审门移植里）。
- **OpenManus PlanningTool 状态机**（A 类，2-3h）——create/update/mark_step/set_active 持久计划对象，优于一次性 todo 列表。落点：工具注册。

### 维度三：上下文工程（DSH 创新 + 狩猎最大收获，B 类为主）

一个关键发现：**DSH 事件溯源、OpenHands Condenser、Pi 分层压缩是同一族技术**——事件是 append-only 事实日志；压缩是对事件的半窗分层摘要（前一半摘要成单事件，后一半不动）；七段式摘要（Goal/Constraints/Progress/Key Decisions/Next Steps/Critical Context）保证"摘要再被摘要"不丢信息。三者合成一个设计：

- **v1.5：事件溯源层（⑨）**——每步行为记 append-only 事件（会话=事实日志/agent=实时通道/tools=策略管道，DSH 三分域），QRA 长研报流水线天然可审计可回放。落点：新扩展面（事件日志钩子）。
- **v1.5：分层压缩（⑩）**——Pi M1 的边界切割（只在对话边界切，绝不切进工具结果序列）+ split-turn 半回合处理 + 增量 UPDATE 摘要 + OpenHands 软/硬触发分离。七段式摘要天然映射研究任务追踪。
- **v2.0：Manus 策略层（⑪）**——可逆压缩优先（丢网页正文留 URL、丢文档留沙箱路径，永远可找回）+ 工具遮蔽而非移除（保缓存）。
- **v1.0 立刻做的一件事（A 类）**：**Pi M2 缓存纪律**（2-3h）——缓存断点打在最后一条用户消息；缓存键与会话绑定；摘要调用单独隔离缓存键防污染；逐消息记账 cacheRead/cacheWrite。LLM 调用层改造，不碰循环，直接降 token 成本。

### 维度四：工具与执行安全

- **smolagents CodeAgent 代码块动作**（A 类，1-2 天）——动作=Python 代码块而非 JSON 工具调用，一次 action 完成"拉数→清洗→计算"，官方实测省 ~30% 步数。量化研究动作形态天然同构，Python 同栈。落点：工具注册加一个 code_action 执行器。**若 v1.0 时间不够，下移 v1.5。**
- **Pi M3 截断防护**（A 类，1-2h，零风险先做）——stopReason=="length" 时整体拒绝执行该消息的全部工具调用，回错误让模型重发。量化场景执行截断参数=脏数据。
- **Codex execpolicy 执行白名单**（A 类，2-3h）——声明式策略文件：前缀规则 Allow/Prompt/Forbidden + 网络域名规则。防 QRA 误删数据/乱写盘。

### 维度五：子代理编排

- **基底**：Hermes async_delegation。
- **增强（v1.5）**：DSH 五派发模式（emit/parallel/serial/bail/waterfall）作为子代理编排策略库——研报多段采集正好用 bail（任一失败即停）+ waterfall。smolagents managed_agents（子 agent 干净上下文包装成工具）+ Manus Agentic MapReduce（结构化结果返回）。工作量 1 周级别，v1.5 立项。

### 维度六：技能与契约（你要的"Claude 专业"）

- **基底**：Hermes 已兼容 SKILL.md（name≤64/desc≤1024 开放规范）。
- **增强（A 类，1-2h）**：Goose recipes 的参数替换思想——SKILL.md 带 `arguments` 参数注入 + 资产文件随行（数据源模板打包），研究 playbook 声明化。
- **决策记录制度（A 类，与开源同步做）**：DSH Agent Notes 制度——每次变更附"决定+否决+后果"。

## 四、分期路线图

### v1.0（W1-8）目标：真跑通 + 真实分数
- 骨架就位：钉 commit、解封依赖、源码留存（W1）
- 领域层：quote/signal/kb_fts/日报/verifier（W1-3）
- A 类嫁接：评审门移植（W4，最大单块）、缓存纪律、截断防护、execpolicy、Mem0 增量、记忆权限分离、Dream cron、PlanningTool（W4-6）
- QRA-Bench 30 题 + Claude Code 对比 + 幻觉率（W5-8）
- 验收：30 题真实分数 + 每嫁接件组件级测试通过 + 每周成本周检（>¥350/周停机）

### v1.5（W9-12）目标：事件溯源 + 分层压缩
- ⑨⑩两个扩展面立项：优先绕，绕不过打洞
- CodeAgent 代码块动作（若 v1.0 没做）
- 子代理五派发模式
- 验收：长会话（>100 步）不回退、可回放、压缩不丢早期决策

### v2.0（12 周后）目标：记忆与策略的下一代
- ⑪ Manus 压缩策略层 + ⑫ Letta 分块自编辑记忆
- C 类清单复盘：若已凑三条，此时带数据立项深度重构
- 验收：分块记忆自编辑跑通 + 压缩可逆性测试

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 嫁接件太多导致 v1.0 又变"大而全"死法 | 砍的顺序已定（第五节）；每件嫁接独立测试通过才进主分支；A 类 7 件里 5 件是 1-3h 小件 |
| 评审门移植是最大单块，最可能失败 | W4 专攻；移植前先读通 background_review 入口；失败则降级为"评审终稿"弱形式（先跑通再增强），记录决策 |
| B 类扩展面打洞违反铁律 | 每个扩展面单独评审：先找 provider 面外挂弱形式（如记忆层压缩而非上下文层压缩），绕不过且价值确认才打洞，打洞=最小 diff |
| 长会话压缩弄丢早期决策 | 七段式摘要 + 增量 UPDATE + 验收测试（压缩后问早期问题对比答案） |
| 成本 | 周检制度保留；Pi M2 缓存纪律预计压掉大头；Hermes 192k tokens/任务基数本来就低 |
| 三支狩猎队的结论未全部源码复核 | 标注来源分级：Pi 三个机制有文件:行号【源码验证】；记忆/扫描报告为【狩猎声称】，落地前各自复核对应源码 |
