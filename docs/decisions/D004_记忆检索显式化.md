# D004：自动记忆不注入系统提示词，回忆走显式检索

- 状态：accepted
- 日期：2026-08-14

## 背景

qra_memory provider 落成后，记忆有两种暴露方式：①每次会话自动注入 system prompt
②靠模型主动调 qra_memory_search 检索。方式①看似"更智能"，但每会话都塞全量记忆 =
token 成本线性膨胀 + 无关记忆污染注意力（类似 Hermes 上游 MEMORY.md 的老问题）。

## 决策

- 自动记忆（qra_memory_add 写入）**不**自动注入 system prompt（system_prompt_block 只显示契约计数）
- 回忆 = 模型显式调 qra_memory_search（工具描述写明"先检索再回答"）
- 契约类记忆（kind=contract）只读，由同一检索工具暴露

## 备选项

- 全量注入：成本与污染不可控；与上游"skip_memory 防泄漏"哲学同向而行的理由不成立
- 双轨（注入最近 N 条 + 检索）：复杂度收益不成比例，暂不

## 后果

- W7 长程评测 3/3 通过：跨会话写入→新会话检索回忆→判重，全部走显式路径
- 风险：模型"忘记"检索直接回答 → 由 bench 题与 prompt 引导覆盖（M01B 已验证会调）
- 上游 fork 记忆走 MEMORY.md 不进 provider——两条记忆线并存，文档已写明边界
