## 第一部分 · 设计哲学（四仓库共识，一切设计的出发点）

### P1. 核心循环最小化
DSH 原话："This is the only package that contains concrete loop logic. Everything else is a plugin."
- 主循环 = 调模型 → 跑工具 → 重复。**其余全部是钩子/插件/事件监听器**。
- QRA 推论：主流程只留 `取数 → 算信号 → 写报告` 三段，每段暴露 2-3 个钩子（signal/pre-compute、report/pre-render…）。
- 新功能 = 新监听器，永远不改主流程。

### P2. 防御性工程（默认会出错，用代码兜底）
- prime-agent：基线快照冲突拒绝、原子写、回滚可回滚、评审门双保险
- Hermes：字符预算、文件锁、威胁扫描、漂移检测备份、永不真删
- 推论：所有状态写入必须 = 临时文件 + rename 原子替换；所有 LLM 输出必须过结构校验；所有删除必须可恢复。

### P3. 状态有边界（一切皆是显式预算）
- 前缀缓存：Hermes 冻结快照（会话中不改变量提示词）
- 上下文：DSH compaction 压力触发、Claude 渐进披露（目录→正文→参考）
- 记忆：Hermes 字符预算（2200/1375）逼模型合并
- 推论：上下文、记忆、工具结果——每个都有显式上限，超限走降级路径（spill/压缩/报错）。

### P4. 可恢复性优先（一切可落盘可重建）
- Hermes SQLite WAL；DSH 事件日志折叠；prime kernel-state dill 快照
- 推论：状态 = 纯函数(事件日志)，崩溃恢复免费；**内核变量 = 工作记忆，dill 快照跨会话恢复**。

### P5. 制度是架构的一部分
- DSH：505 条 Agent Notes、feature→mechanism map、简化纪律（48 条删除决策）
- prime：评审门过滤噪音、最小编辑、作用域治理
- 推论：每个变更附"决定+否决了什么+后果"；每季度主动删冗余。

## 第二部分 · 记忆系统（学 Hermes + prime kernel）

### 2.1 四层记忆架构（Hermes 坐标系）

```
┌─────────────────────────────────────────────────────┐
│  Layer 0: 内核工作记忆（prime 原创 · IPython 命名空间）  │
│  变量/DataFrame/模型/中间结果 —— dill 快照跨会话恢复     │
├─────────────────────────────────────────────────────┤
│  Layer 1: 热记忆（Hermes · 每轮注入，预算封顶）          │
│  MEMORY.md(2200字) + USER.md(1375字) · 冻结快照         │
├─────────────────────────────────────────────────────┤
│  Layer 2: 温记忆（Hermes · 每轮 prefetch）             │
│  外部 provider（Honcho/Mem0…）8s 超时 · 闲聊跳过        │
├─────────────────────────────────────────────────────┤
│  Layer 3: 冷记忆（Hermes · 按需检索，零 LLM 成本）       │
│  SQLite FTS5 + trigram（CJK）· 历史研报/日报/结论        │
└─────────────────────────────────────────────────────┘
```

### 2.2 内核工作记忆（prime 的原创设计——之前漏读的）

**机制**（源码：packages/coding-agent/src/core/kernel/state-snapshot.ts）：
- IPython 内核 = agent 的持久笔记本，变量跨调用存活
- 会话结束/恢复时：`buildSnapshotCode` 用 **dill** 序列化用户命名空间每个顶层变量
- 跳过：下划线开头、IPython 内部名（In/Out/get_ipython）、不可序列化对象（open file/socket/GPU tensor）——**逐个变量独立序列化，单个失败不影响整体**
- 恢复时 `buildRestoreCode` 逐名注入命名空间
- 256MB 上限，超限变量跳过并报告
- bootstrap 时注入 `rlm` 运行时 + python skills（`_PrimeAgentCallableSkillModule` 包装模块使其可 await 调用）

**QRA 推论**：
- QRA 的 kernel 会话保持 `df_signals`、`latest_signal`、`report_state` 等变量
- 会话快照到 `data/kernel-state.dill`，恢复时自动注入
- 这是"研究中间状态不丢"的根本保障——比文件落盘更自然

### 2.3 热记忆：冻结快照 + 字符预算（Hermes）

- 会话开始：渲染 MEMORY.md + USER.md 为**冻结块**注入系统提示词（保前缀缓存）
- 会话中写入磁盘但**不改系统提示词**（下会话才生效）
- 容量：硬字符预算（不用 token——模型无关）；满即报错 + 列出条目，逼模型当场合并（apply_batch 原子批处理：删旧+改短+加新，一次调用）
- **不写自动淘汰算法**——淘汰判断交给模型，约束交给字符数
- 写入守则（MEMORY_GUIDANCE）：用户偏好/纠正 > 环境事实 > 流程；一周内过期的别存；写"陈述事实"不写"命令自己"；流程归技能不归记忆

### 2.4 温记忆：prefetch 预取（Hermes memory_provider）

- 每轮 API 调用前 `prefetch(query)`：按当前用户消息预取相关记忆注入
- 后台线程预取下轮（8s 超时，失败不阻塞主对话）
- 无信息量消息（闲聊/打招呼）跳过预取

### 2.5 冷记忆：FTS5 + trigram（Hermes hermes_state_search.py）

- SQLite WAL + FTS5 双表（默认 unicode61 + trigram 用于 CJK）
- 查询清洗 `_sanitize_fts5_query`：引号短语保护 → 特殊字符剥离 → CJK 判定 → 布尔操作符清理 → 点号连字符加引号
- 路由：`_trigram_eligible_tokens`（全部 token ≥3 字符才走 trigram）→ token 逐词加引号 → MATCH → 失败降级 LIKE
- 三档成本：热(每轮~1300 token) / 温(8s prefetch) / 冷(~20ms 免费)

### 2.6 记忆治理闭环

- 写入时：预算错误驱动合并
- 每 10 轮：后台审查 fork（瘦 agent 重放对话，自主决定存什么）
- 定期：curator（技能 30 天 stale / 90 天归档；记忆永不真删只归档）
- 可选：write_approval 写入门控（自动提炼进 pending，用户批准才生效）

## 第三部分 · 迭代系统（学 prime-agent）

### 3.1 双评审门（refinement.ts 源码）

```
触发（四通道）→ 门1评审（便宜·4096tok）→ 门2规划（贵·32000tok）→ 应用（校验+原子写）→ 回滚能力
用户/refine │ 模型refine.run │ 25回合自动 │ 压缩后自动
```

- **门1**（AUTO_REFINE_REVIEW_SYSTEM_PROMPT）：独立小调用，只判断"该不该写"——拒绝噪音/未证假设/瞬时输出；输出 {shouldRefine, rationale, instructions}
- **门2**（REFINEMENT_SYSTEM_PROMPT）：输出严格 JSON edits——{action: create|update|delete, kind: prompt|memory|skill|subagent}
- 强制非推理模式（省预算给 JSON）
- **作用域**：local 默认（会话内），global 显式（跨会话稳定教训）

### 3.2 应用与并发控制（applyRefinementProposal）

- 逐条校验：base_prompt 硬拒绝、skill 必须带可执行契约（reference.type=python + import + callable + arguments）
- **基线冲突拒绝**：规划前拍 baseline 快照，应用前重读比对，变了就拒单条
- 原子落盘：临时文件 + rename（保留 0600 权限）
- 部分成功：单条非法不影响其他合法 edit
- **回滚**：before/after 全量快照反向重放，回滚本身也可回滚，跨会话可回滚（global refinements.jsonl）

### 3.3 提示词压缩目录（formatHarnessStateForPrompt）

- 每类最多 6 条 × 每条 180 字符摘要 × 带版本号
- 明确标注"只是路由提示，细节按需查看"——harness 再大不污染上下文

## 第四部分 · 架构系统（学 DeepSeek Harness）

### 4.1 事件三分域（2026-06-30-event-domain-semantics.md）

| 域 | 性质 | 用途 |
|---|---|---|
| 会话事件 | 事实日志（持久·可回放·只装JSON） | 状态重建 |
| agent 事件 | 实时通道（携带活对象·可拦截） | 运行时控制 |
| tools 事件 | 工具管道（pre/post 钩子） | 工具链 |

**铁律：持久事实必须进会话日志，绝不镜像成实时事件。**

### 4.2 四派发模式

- 瀑布钩子（层层传递可改写）：agent/pre-step, agent/request, tools/pre-execute
- 串行钩子（等完）：agent/turn-stopping
- 并行钩子（独立执行）：session/flush
- 即发即忘（通知）：agent/status

### 4.3 能力接缝三角色

```
契约包（只声明接口）→ 实现包（具体后端）→ 消费包（模型工具）
换实现 = 换一个包 + 改一行配置，接口不变
```

### 4.4 折叠投影恢复状态（DSH）

- 状态 = last-wins 日志事件 + 纯函数折叠 → 重启/回放/fork 自动恢复
- 品牌类型（Branded<'GoalId'>）防跨进程 ID 混淆
- **模型可见 ⟺ 已记录** 不变式：任何进入模型请求的内容必须能从会话日志重建

### 4.5 工具管线（dsh-tool-skill）

```
tools/pre-execute(权限) → tools/execute → tools/post-execute(结果处理) → tools/result(最终观察)
```
- spill：大结果(>阈值)落盘，模型只见 locator + retrievalHint
- 存储失败不把成功调用变失败（best-effort）

### 4.6 压缩（dsh-compaction）

- 压力判断在**下一 pre-step 边界**（工具结果落定后压力才准确）
- 溢出恢复挂 agent/request-error（context-window-exceeded 时压缩重试）
- 容量事实归模型适配器（按 {provider,model} 精确路由选阈值）

## 第五部分 · 研究系统（学 Claude Code）

### 5.1 一切皆文件契约（frontmatter 即接口）

```
命令 = commands/*.md（description<60字·allowed-tools·model档位）
子代理 = agents/*.md（name·description带<example>触发·model·tools最小权限）
技能 = skills/<名>/SKILL.md（元数据→正文→references 三层渐进加载）
钩子 = hooks/hooks.json + 脚本（PreToolUse/PostToolUse/Stop…9事件）
```

### 5.2 描述即路由

- 子代理/技能不靠硬编码调用，靠 description 的触发场景 + <example> 匹配
- 模型自己当路由器

### 5.3 验证闭环（deep-research 模式）

- fetch 子代理抓取 → 抽取 claims → verifier 逐条核验 → **区分"未验证"vs"被证伪"**
- 信心分 0-100，阈值 80 过滤假阳性
- 每个关键结论先入"结论清单"，独立核查代理逐条验证，不过不进报告

### 5.4 迭代循环控制面（Ralph 插件）

- Stop 钩子拦截退出 → 读 transcript → 未见 `<promise>完成词</promise>` 就 block 并喂回
- 状态全在文件（迭代数/完成词/原始提示词），max-iterations 逃生舱

### 5.5 钩子协议

- PreToolUse 返回 {permissionDecision: allow/deny/ask} + 可改工具入参
- Stop 返回 {decision: approve/block} + reason
- matcher 正则匹配工具名、if 匹配命令模式、asyncRewake 后台异步唤醒

## 第六部分 · 子代理系统（DSH continuable + prime fork + Claude 并行）

### 6.1 DSH continuable 子代理

- one-shot（一次性委托）vs continuable（持久会话可冷恢复）
- **authority 校验**：只有直接父代理能 followup；冷恢复前再验 authority
- 会话树：listChildren/listDescendants（parentId + depth 预序遍历）
- 子代理能力 = 父 preset 组合 + 自身 persona + tool filter（`applyChildComposition` 强制带父参数）

### 6.2 prime 内核 fork（fork-server）

- 每 (python, cwd, env) profile 一个 forkserver，内核 fork 而非冷启动
- 子代理可继承/隔离内核状态（macOS 禁用 fork，Linux 默认开）

### 6.3 Claude 并行子代理 + 信心分

- 探索阶段派 2-3 个并行子代理摸不同角度
- code-review：4 代理独立审 + 每条问题独立验证 + 信心分<80 丢弃
