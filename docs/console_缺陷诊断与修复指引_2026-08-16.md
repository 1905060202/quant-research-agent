## 1. 用户报告的症状

1. 输出有大量重复，且屏幕不会自动跟随下移。

## 2. 问题一：重复输出 + 屏幕不跟随下移

### 根因

`src/qra/console/main.py` 用 rich `Live` 做**全帧重绘**：

- `main.py:39` — `from rich.live import Live`
- `main.py:528-529` — `live = Live(render(...), refresh_per_second=20, vertical_overflow="visible")`
- `main.py:296-328` — `_render_loop` 在每次事件 drain 后调用 `live.update(render(...))`
- `main.py:90-124` — `render()` 每帧从零重建整轮（`Group` 拼接所有 block），
  其中 thinking 块用 `Panel` 包 `Markdown`（`main.py:103-106`），tool 块用
  `Panel` 包边框（`main.py:142-166`）

机理（原文见 D011 §问题根因第 1 条）：`Live` 的机制是「光标上移 N 行 →
整帧重印」。当流式 CoT 长到超过终端高度时，上移行数与实际不符，帧与帧互相
覆盖、同样内容被重复打印，且终端永远不发生自然滚动——**两个症状同源**。

加剧因素（执行 agent 修复时要一并考虑）：
1. deepseek 的 reasoning 是逐 token 流式到达，每个 `reasoning`/`delta` 事件
   都触发一次全帧重建 + 重印，叠加 `refresh_per_second=20`，重印频率极高，
   覆盖错位被无限放大。
2. thinking 块每帧都重新 `Markdown(...)` 解析 + `Panel` 画框，高度计算随
   markdown 渲染结果漂移，进一步加剧「上移行数对不上」。

### 修法

按 D011 §1：**废弃 `Live`**，新建 `src/qra/console/renderer.py`（追加式流式
渲染器）。核心原则：

- 已定型内容只 `print` 一次——自然滚动（终端自动跟随）、scrollback 完整、
  从结构上消灭重复帧。
- 唯一原地刷新的是「活动尾部」：一行 spinner（`\r` 原地重画，0.1s 心跳），
  内容到达先擦 spinner 再追加。
- CoT：无框，灰暗（`grey62`）逐 token 流式追加；块头 `✻ 思考`、块尾
  `✻ 思考 · 用时 Xs`。
- 文本块：流式期间按原样追加，块闭合时区域重印为 rich Markdown。
- 工具块：默认折叠为一行 `⏺ 工具 name(args摘要) · 时长 · ✓ · 结果 N 字 ▸`；
  子代理（`delegate_task`/`spawn*`）标题 `⎇ 子代理`。
- usage footer 保留（含 `¥`，见 §7 门禁标记）。

**必须保留的坑**：`main.py:522-527` 已发现并绕过——`run_conversation` 期间
`redirect_stdout` 会把 `sys.stdout` 换成 `StringIO`，而 rich `Console` 无
`file` 参数时会动态跟随 `sys.stdout`，导致渲染帧被吞进缓冲区（表现：整轮
屏幕空白、结束后内容一次性涌出）。追加式渲染器**必须显式绑定真实 stdout**
（`Console(file=sys.stdout)`，或自行 `os.write(1, ...)`），否则会重新踩这个坑。

## 3. 问题二：`/` 输入无提示

### 根因

`src/qra/console/input_layer.py` 只有 Tab 补全，没有 live 命令面板：

- `input_layer.py:318-327` — Tab 分支：只有**按 Tab** 且 draft 以 `/` 开头才调
  `self._completer(d)`；不按 Tab 就什么都不弹。
- `commands.py:68-88` — `complete()` 只做前缀匹配（单候选补全 + 空格 /
  多候选最长公共前缀）。
- `input_layer.py:57-58` — `InputLayer.__init__` 签名只有 `completer` 参数，
  **没有 `menu_provider`**。
- `input_layer.py:286-297` — `_dispatch_csi` 只处理 `↑` `↓`，`←→` 明确忽略
  （注释「P1 再实现」）。

所以用户敲 `/` 时没有任何面板弹出——这正是「残血版」体感的直接来源。

### 修法

按 D011 §3：新增 `menu_provider(draft) -> [(名称, 描述)]`：

- draft 以 `/` 开头且无空格时弹出面板（提示符下一行起，反显高亮当前项），
  随输入过滤。
- `↑↓` 在面板打开时导航面板（关闭后恢复历史导航）；`Enter` 选中补全并加
  空格；`Tab` 补最长公共前缀；`Esc` 关闭；其他字符继续过滤，无匹配自动关闭。
- 面板重绘 = 原地重写面板行 + 回到提示符行重印 prompt+draft。

## 8. 风险与边界（诚实记录）

- 点击展开是对「已渲染区域」的重印，滚动条位置之外的点击在部分终端可能偏行
  （终端高度变化引起）；v1 不做整屏 TUI（D011 §2 已知边界）。
- 流式期间 markdown 半成品按原文显示——与 CC 的「流式渲染 markdown」有差距，
  已在 D011 记录，P1 可做段落级 markdown 流式。
- `renderer.py` 是后续 P1 功能（整屏 TUI / 光标编辑 / todo 面板 / plan mode /
  skills UI / hooks UI）的地基，不要把渲染器写死成只服务当前两个问题，留出
  「块」的抽象（id/种类/全文/折叠态），供后续功能复用。
