## 二、为什么这个结论站得住

1. 雅宁对"完整体"的定义 = 真实 fork + 改核心（工具注册/记忆 provider/评审门移植），不是给现成 harness 写技能。Hermes 是唯一满足这个定义的 Python 底座。
2. 反对 Hermes 的最重武器（DeepSeek bug 簇活跃）已被对抗审计证伪：6/9 issue 2026-04 已闭环，HEAD 源码 message_sanitization.py 已内置 reasoning_content 回传策略。
3. Hermes 的真实代价在文档里重新算过：体量（cli.py 895KB，但我们不碰核心）、依赖 == 锁定（改造要解封）、周更 tag 跟随。这三条都是"改造阻力"，不是"兼容风险"，可控。
4. prime 保留为：QRA-Bench 评测时的对照 harness（不选它，不等于不用它验证）。
