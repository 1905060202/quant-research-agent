## 三、W1 三个坑（已写成 QRA 定制层知识）

1. **auth.json 里没有裸 token**：`~/.hermes/auth.json` 的 credential_pool 只存凭据元数据+指纹（id/label/source/secret_fingerprint），没有 secret 本体。把整个 pool JSON 当 token 用 → httpx `LocalProtocolError Illegal header value`，被 Hermes 笼统报成 "Connection error"，误导排查方向。**正确来源**：`~/.claude/settings.json` 的 `ANTHROPIC_AUTH_TOKEN`（与 CC 同款，⚠️ 待轮换）。run_qra.sh 已按此提取，零落盘。
2. **PluginContext.register_tool ≠ registry.register**：插件面签名是 `(name, toolset, schema, handler, check_fn, requires_env, is_async, description, emoji, override)`，**没有** `max_result_size_chars`。多传一个参数插件就静默加载失败（错误只进日志，agent 会话照常启动，模型甚至会自己编"插件在别的 profile"的解释）。
3. **插件 handler 契约是 `(args: dict, **_kw)`**：registry.dispatch 把模型参数 dict 当第一个位置参数传，task_id/session_id/user_task 走 **kw。bundled spotify/google_meet 全部如此。typed-kwargs 写法（`def qra_quote(symbol, task_id=None)`）会让 symbol 收到整个 dict——模型在会话里"帮我改"的签名就是错的，已按源码契约重写。
