# QRA 全局宏观设计总纲（Blueprint）

> 权威源：本文是「这个系统为什么这么设计、接下来往哪走、怎么走」的唯一答案。
> 性质：**总纲**。architecture/development 是细则，ADR 是单项决策，本文是纲。
> 给谁：①flash 模型执行者——§5 是你工作的全部边界；②任何接手者——§1-§4 一小时读懂全局。
> 修订：本文修订是**设计层任务**（见 §7），执行者不得自改。

## 0. 为什么写这份总纲

2026-08-17，DeepSeek API 涨价，pro 模型的 token 费用已无力长期负担。但 pro 与 flash
的差异不在执行——写代码、跑门禁、照单移植，两者差别不大；差异在**设计**——架构怎么
切、机制怎么定、协议怎么立、问题怎么想透。所以趁 pro 还可用，把设计层想清楚的东西
一次性写下来，之后 flash 照总纲执行，pro 只在低峰期做设计。

这份总纲 = 设计层与执行层的**契约**。设计层承诺「问题想透、方案定死」；执行层承诺
「照单实现、门禁验证、如实报告」。

## 1. 系统全景：我们造了什么

### 1.1 一句话

QRA（Quant Research Agent）= **hermes-agent 骨架（零修改）+ QRA 嫁接层（全部能力）+
量化领域层**，2026-08-14 立项，已开源（public + MIT）。骨架负责「怎么思考、怎么记、
怎么执行」，嫁接层负责「量化研究怎么做」，领域层负责「量化问题怎么解」。

### 1.2 五层图（每一层为什么在）

```
入口层    bin/qra 一个入口三种模式：console（CoT 全展示）/ -z 单发 / sync 同步
嫁接层    .hermes/plugins/ 五个插件，全走官方插件面（D002 的答案）
底座      vendor/hermes-agent pin 11c5aae，零修改——它是引擎，不是资产
上游      prime（essence）· dsh（essence）· hermes（managed）——前沿情报源
评测层    bench/ 30 题 ×3 域——一切改动的裁判
```

### 1.3 三个数字

- **30 题 QRA-Bench 100%，幻觉 0/30，长程记忆 3/3**（2026-08-14 基线）
- **七层门禁 + 两冒烟 + 零凭据扫描 + 文档核对**——每行改动都要过的关
- **命令面 15/95、console 审计 17 健壮性 + 20 设计发现**——存量优化的主战场

### 1.4 组件咬合关系（设计约束如何互相成就）

系统不是零件的堆叠，是约束的咬合。看懂这五组咬合，就看懂了整个系统：

1. **D002 零修改 → GRAFT_PATHS → qra sync 核对 → vendor_sync_log 账本**。
   底座冻结逼出嫁接面登记制度：任何 import/改写 hermes 内部模块都必须登记，否则
   上游更新时核对拦不住漂移。冻结不是保守，是让上游进化可以持续吸收。
2. **验证铁律 → 七层门禁 → CI 零 secret**。验证义务倒逼门禁可离线化：CI 跑离线层，
   本地跑全层，口径一致。门禁不是仪式，是快速迭代（两天 20+ 提交）不塌的护栏。
3. **单写入者 → console v4 帧 → #73/#74 系列修复**。终端只有一根笔：渲染线程与
   输入线程的所有输出都经 TermIO 一把锁。这个原则确立后，两次崩溃根因（多行粘贴、
   ESC 注入）都是「违反单写入者语义的字节进入了帧区」——修复都是回到这个原则。
4. **开源（public+MIT）→ 零凭据 → 脱敏红线**。push 即发布：key 走 env 注入、
   扫描进 CI、kb_sources 入库前脱敏、隐私只进 gitignored 的 .hermes/memories/。
5. **动态 gold → 机械评分 → 诚实报告**。评测防时间衰减（gold 运行时重采）、
   评分无主观（0/0.5/1 机械判）、分数照实说——benchmark 才是迭代的方向盘。

### 1.5 走到今天的脉络（一句话版）

四仓库精读 → v3-v8 五次推倒 → 融合架构拍板（D001/D002）→ W1-W12 底座/工具/记忆/
日报/评测/长程记忆/开源全落地 → D007 持久内核 + prime 完全体 → D009 三上游同步 →
D010 ARC-AGI-3 挑战立项 → D011 console 渲染重构 → #73/#74 console 崩溃根治与全面审计。
细节在 `docs/拍板记录_2026-08-14.md` 与 W 系列，读来溯源，不作为现状执行。

## 2. 设计原则全书（执行者对照用）

每条：**原则一句话 → 为什么（教训出处）→ 怎么用**。执行任何任务前对照一遍，
违反任何一条的产出 = 返工。原则是内功，不是模板——应用时自然体现，不显式声明。

### A. 架构原则

**A1 底座冻结、嫁接面生长**（D001/D002）。vendor/hermes-agent 零修改；新能力一律
src/qra/ 或 .hermes/plugins/。为什么：底座是上游维护的引擎，改一行就永久失去免费升级。
怎么用：新需求先问「能不能插件解决」；必须碰 hermes 内部模块 → GRAFT_PATHS + 账本双登记。

**A2 不可逆决策 ADR 化**。底座选择、数据口径、协议、安全边界这类「影响后续一切」的
决策落 docs/decisions/DNNN_*.md（背景→决策→备选项→后果）。为什么：别人问「为什么长
这样」要能从 ADR 查到全部答案。怎么用：新决策先看 ADR 有无先例；有冲突先写新 ADR 再动代码。

**A3 插件必须注册 toolset="qra"**。否则工具静默不可见——2026-08-16 实坑（vendor_sync_log
#11），六层门禁全绿也拦不住，因为早期测试绕开了插件发现路径。怎么用：新插件必带一条
走真实注册/加载路径的 e2e 测试。

### B. 工程原则

**B1 验证铁律：任何产出验证 2-3 次通过才说完成**（最高铁律，优先级高于一切）。
门禁 + 冒烟 + 文件证据，三者齐才算过。为什么：没验证就说「通了」的教训反复发生。
怎么用：「做完了」三个字后面必须跟着验证证据，否则视为没做完。

**B2 单写入者**。终端/文件/账本，每个写入面只有一根笔；多线程协作靠锁，不靠祈祷。
为什么：2026-08-16 打字崩终端的根因就是渲染线程与输入线程互踩；#73/#74 的注入漏洞
都是绕过单写入者语义的字节。怎么用：新增输出路径先问「走 TermIO 吗？持锁吗？」。

**B3 拦截在变更之前（validate before mutate）**。任何校验必须在数据变更之前，
副作用不可逆。为什么：栈板堆叠校验放增量之后的教训——先污染再拦截，等于没拦截。
怎么用：写校验逻辑时先问「这行状态此刻已经脏了吗」。

**B4 溯源优先**。改任何代码前 grep/read 现有实现与 vendor 母本；实体/Mapper/DAO
三者写前 grep 确认一致；接口看签名不看描述。为什么：凭记忆写代码反复出错；
描述相同≠同一接口（删过生产打印接口）。怎么用：动手前先花两分钟把改动面读全。

**B5 重写不打补丁**。大改直接从头重写文件，不叠 patch。为什么：patch 叠 patch 会
破坏原有设计与健壮性——#74 审计的委托原话。怎么用：改动超三处相关逻辑，就整段重写。

**B6 测试走真实路径**。测试要经真实的注册/加载/入口链路，不直测模块函数。
为什么：绕开插件发现的测试让 toolset 不可见 bug 全绿漏网。怎么用：新插件必有
真实入口 e2e；冒烟不信模型嘴说，要文件双证据。

**B7 错误落盘**。异常兜底三件套：try 包住循环体、异常写错误文件、状态机不乱。
为什么：TUI 的血泪教训——没兜底就整个会话死掉。怎么用：任何线程的循环体都要有
兜底，异常永远不裸抛到终端。

**B8 简单任务更要想清楚**。类型不一致、未初始化、渲染逻辑倒置、坐标系混淆——
简单任务的反复错误全是「没想就写」。怎么用：写前三秒自问：类型？初始值？方向？
坐标系？边界？

### C. 数据与评测原则

**C1 数据质量门禁：覆盖率 100% 才跑信号**。覆盖率 <100% = 报数据不足，不当结果。
为什么：.SS 后缀映射教训——数据缺一截时信号是垃圾。怎么用：任何量化分析先打印
覆盖率，不足就拒绝出结论。

**C2 动态 gold + 机械评分 + 诚实报告**。评测 gold 运行时重采防时间衰减；评分
0/0.5/1 机械判；分数达不到预期照实说。为什么：benchmark 是方向盘，假分数等于
蒙眼开车。怎么用：改工具面/记忆面跑一次 bench 回归；报告只写实测数。

**C3 双证据判定**。系统行为判定要看落盘证据（审计 jsonl、会话目录、账本行），
不信模型说「我做了」。怎么用：冒烟脚本断言文件与数据，不断言模型输出文本。

### D. 文档原则

**D1 每类信息只有一个权威源**。「历史记录」可读但别当现状执行；现状以 ★ 权威源
为准。怎么用：开工前按 docs/README.md 场景导航读对文档。

**D2 改完顺手改文档**。架构变→architecture.md；新坑→troubleshooting.md（先加条目
再修）；新嫁接→账本；重要决策→ADR+记忆。为什么：门禁和 CI 都拦不住「没写文档」，
只能靠纪律。怎么用：提交前对照 docs/README.md 维护义务表逐项自查。

**D3 落地行文通俗**。文档/注释说人话，黑话只限内部推理。为什么：文档是给人（和
flash）读的，不是给仪式看的。怎么用：写完后问「第一次接手的人能读懂吗」。

### E. 安全原则

**E1 零凭据**。明文 key 永不入库——包括提交信息、注释、测试 fixture、文档代码块。
key 唯一来源 ~/.claude/settings.json 的 env.ANTHROPIC_AUTH_TOKEN，入口脚本自动提取。
push 前 scan_credentials.sh；CI 同款扫描。怎么用：写任何代码/文档前先扫一眼有没有
碰 key 形态的字符串。

**E2 公开即发布，先止血后处理**。仓库 public+MIT，push 就是发布。若误提交凭据：
先轮换 key（止血）→ 再处理历史 → 最后改代码。怎么用：kb_sources 新增文档源先
脱敏（电话/邮箱/微信号/key → 占位符）再入库；隐私类内容只进 gitignored 路径。

**E3 个人隐私永不进公开仓库**。画像/八字/财务明细/持仓金额/亲密关系等只准进
.gitignore 保护的 .hermes/memories/。怎么用：迁移任何记忆时先按此分流。

## 4. 迭代机制：如何跟随业界前沿

### 4.1 三路情报与同步纪律

| 上游 | 形态 | 同步 | 吸收方式 |
|---|---|---|---|
| hermes-agent | managed | qra sync：ff-only → 嫁接面核对（命中即拒）→ 七层门禁 → 失败回滚 | 直接升级 |
| prime | essence | qra sync prime：diff 报告 → 人工逐行审 diff 判重移植 → 推进钉针 | 精华移植 |
| dsh | essence | 同 prime | 精华移植 |

essence 流程的核心：**读源码 → 提取可移植机制 → 判断重移植 → ADR 登记 → 落地 →
门禁 → benchmark 验证**。已完成的吸收案例：prime 完全体（D007）、dsh 的 config_guard
（schema 硬校验）、qra_python 快照与探活。研究笔记在 `docs/机理研究_*.md`。

### 4.2 benchmark 驱动迭代

- **QRA-Bench 30 题**是工具面/记忆面改动的回归裁判（改完跑一次）。
- **ARC-AGI-3（D010）**是架构级的挑战标尺：诚实上榜，机制吸收反哺架构
  （P0 机制：A1 log 双写 / B1 校验门 / B2 假说回测 / C1 EffectRegistry / C10 截断全拒）。
- 原则：**分数是方向盘，不是成绩单**。低了找机制原因，不调口径。

### 4.3 成本纪律与双档节奏

- `scripts/check_cost.py`：¥350/周阈值（连续 2 周超 → 停机复查）。涨价后阈值本身
  需重新核定（I11）。
- **双档节奏**：设计任务（§3 标注「设计」的项 + 新机制/新架构/新协议）攒批，
  低峰期集中做；执行任务（标注「执行」的项）随时 flash 做。
- 长任务（bench 全量、冒烟迭代）后顺手跑一次周检。

## 5. Flash 执行规范（本文档存在的理由）

### 5.1 双档分工

| 档 | 谁 | 做什么 | 什么时候 |
|---|---|---|---|
| 设计层 | pro（低峰期） | 架构切分、机制设计、协议定义、ADR 修订、总纲修订、前沿吸收、疑难根因 | 攒批集中做 |
| 执行层 | flash（日常） | 照单实现、测试编写、门禁运行、已定修法的 bug 修复、文档同步、命令接线 | 随时做 |

**判定表**——拿到任务先分档：

- 归执行层：§3 标注「执行」的项；任何已有明确方案/修法/接口的任务；重复性维护。
- 归设计层：新插件/新机制的形态设计；跨模块重构方案；协议/数据口径变更；
  ADR/总纲/architecture 修订；根因未明的故障；benchmark 分数异常的机制归因；
  「不知道该怎么切」的一切。

### 5.2 升级信号（flash 遇到任何一条，停下来标记，不要硬扛）

1. 同一问题失败 ≥3 次；
2. 任务触及架构、协议、ADR、总纲，或发现文档互相矛盾；
3. 门禁挂死无法定位根因；
4. 需要新接 vendor 内部模块（GRAFT 设计）；
5. 发现「存量问题总表」之外的新问题且修法不显然。

### 5.3 执行 SOP（每次任务的标准路径）

```
1. 读上下文   HANDOFF → docs/README.md 按场景导航 → 相关 ADR → vendor_sync_log 最近条目
2. 三确认     实体/Mapper/DAO 三者 grep 一致；接口看签名；改动面读全（B4）
3. 写码+测试   新行为必须有测试锁定，测试走真实路径（B6）；大改重写不打补丁（B5）
4. 门禁       scripts/verify_qra.sh（改动任何 src/ 或插件后必跑；至少 --offline）
              相关冒烟：console 改动跑 _smoke_console.py，内核改动跑 _smoke_qra_run.py
```
