## 三者的架构哲学对比

| 维度 | prime-agent | Hermes | DeepSeek Harness | QRA 吸收 |
|---|---|---|---|---|
| 状态层 | JSON 文件+缓存 | **SQLite+FTS5 全文检索** | 插件化 session persistence | Hermes 的 SQLite 方案（数据量大后） |
| 记忆 | 四层 harness | **MemoryProvider 插件+prefetch+后台写** | spill(溢出)+compaction(压缩) | Hermes 的 prefetch + DSH 的 spill |
| 技能 | SKILL.md 发现 | skills 目录 | **catalog+按需加载+双调用策略** | DSH 的 catalog 模式（最佳） |
| 子代理 | rlm spawn | async_delegation | **continuable 冷恢复+authority 校验** | DSH 的 continuable 模式 |
| 工具 | python 契约 | tool registry | **tools/pre-execute→execute→post-execute 管线** | DSH 的事件管线 |
| 压缩 | compact | conversation_compression | compaction(压力触发) | Hermes 的 lineage 分裂 |

## 吸收的 10 个新设计（D9-D18）

### D9 · SQLite 状态层（Hermes hermes_state.py）
- WAL 模式（并发读写）+ FTS5 全文检索（会话消息可搜索）+ 会话 lineage（parent_session_id 链）
- QRA：数据量大后（日报历史/验证卡累积），从 JSON 升级 SQLite；FTS5 做知识库全文检索（比 bigram 关键词强）

### D10 · MemoryProvider 插件化 + prefetch（Hermes memory_manager.py）
- providers 列表：add_provider/get_provider；**会话开始时 prefetch_all(query) 预取相关记忆**
- 后台异步写入（_submit_background）+ 会话边界 commit
- QRA：记忆层升级为"多 provider"（偏好/验证卡/方法论），每轮开始时按当前话题预取

### D11 · 技能 Catalog + 按需加载（DSH dsh-skill）
- 模型只看到 name+description 目录（catalog），点开才加载正文（progressive loading）——**控制上下文占用**
- 双调用策略：modelInvocable/userInvocable 分离
- 目录变化用 digest 检测，变化才重发
- QRA：方法论库 → skills/ 目录 + SKILL.md；LLM 先看目录，需要时再调 skill 工具加载正文

### D12 · 工具执行管线（DSH dsh-tool-skill）
- tools/pre-execute（权限检查）→ tools/execute → tools/post-execute（结果处理）→ tools/result（最终观察）
- QRA：工具调用加 pre/post 钩子（记录指标、脱敏、重试）

### D13 · spill 溢出机制（DSH dsh-spill）
- 大工具结果（>阈值）落盘保存，模型只看到 locator + retrievalHint
- QRA：知识库检索返回大块时，先 spill 到文件，回答里给引用而非全文

### D14 · 子代理 continuable（DSH dsh-subagent）
- one-shot（一次性）vs continuable（可冷恢复，持久 session）
- **authority 校验**：只有直接父代理能 followup
- QRA：Planner/Analyst 用 continuable 子代理（跨轮次保持），结果 reportFrom 回传

### D15 · 事件驱动架构（DSH agent-loop）
- 一切通过事件：agent/pre-step, tools/execute, agent/request-error... 插件监听事件扩展
- "Everything that goes beyond call-model-run-tools belongs to plugins"——**核心循环保持最小，功能全在插件**
- QRA：主循环只做"调模型→跑工具→重复"，指标/记忆/反思全做节点外钩子

### D16 · 压缩压力触发（DSH compaction / Hermes compression）
- 在 agent/pre-step 检查上下文压力 → 超阈值触发压缩 → lineage 分裂新 session
- QRA：上下文超阈值时，把旧对话归档+摘要，开新 session 链（保留历史可查）

### D17 · 会话交接（Hermes request_handoff）
- 明确 handoff 状态机：request→claim→complete/fail——会话间任务交接
- QRA：Planner→Analyst 之间用 handoff 而非直接消息（可追踪状态）

### D18 · 消息源标记（DSH skill-invocation MessageSource）
- 消息带 source 元数据（谁注入的/什么形式），消费端按 metadata 重建而非重解析
- QRA：所有注入内容（系统提示/工具结果/技能正文）打 source 标记

## 落地优先级（QRA v4）
- P0 今天：D11 技能 Catalog（方法论 skills/ 化——用 DSH catalog 模式，这是最有区分度的一个）
- P1 本周：D13 spill（大结果落盘）+ D15 事件管线（工具 pre/post 钩子记指标）
- P2 下周：D10 记忆 prefetch（多 provider）+ D14 continuable 子代理
- P3 数据量大后：D9 SQLite 升级 + D16 自动压缩

## 关键设计原则（三源码共识）
1. **核心循环最小化**：agent-loop 只做"调模型→跑工具→重复"，其余全插件（DSH）
2. **渐进加载**：目录先、正文后（DSH skill）；记忆先 prefetch 关键、不塞全部（Hermes）
3. **可恢复性优先**：所有状态可落盘可恢复（Hermes SQLite / DSH persistence）
4. **观察优于控制**：事件全广播，谁需要谁监听（DSH）
5. **状态有边界**：会话 lineage、spill、compaction 都是"控制单个上下文大小"的手段
