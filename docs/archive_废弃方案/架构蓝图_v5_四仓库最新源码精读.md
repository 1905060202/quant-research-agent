## 二、最新版 vs 本地版的重大差异（必须知道）

### Hermes（差异最大）
- ❌ 本地认知"Tier1/Memory/KB 三层" → ✅ 实际是"**系统提示词三段缓存（stable/context/volatile）× 四类存储（热记忆/温provider/冷FTS5/技能库）**"
- ❌ curator 管记忆 → ✅ curator 只管技能；记忆整理=写入时预算驱动合并+每10轮后台审查 fork
- ✅ 新增 8 个外部记忆 provider（Honcho/Mem0/OpenViking/Hindsight/Holographic/RetainDB/ByteRover/Supermemory）
- ✅ 新增：apply_batch 原子批处理、write_approval 写入门控、威胁扫描+漂移检测、[SKILL_PRUNED] 幽灵技能防御、session_search 会话血统去重
- 🔑 **反直觉点：记忆没有自动淘汰算法**——用"字符硬预算+报错逼模型当场合并"替代 LRU/评分

### prime-agent
- 旧四点（评审门/最小编辑/作用域/回滚）全部成立 ✅
- ✅ 新增：并发控制体系（baseline 快照冲突拒绝+原子写+mtime 同步+100+并发回归测试）
- ✅ 新增：计划/应用两阶段分离（规划后台跑，不阻塞对话）
- ✅ 新增：评审门可注入（AutoRefineReviewer）、skill 双重可执行契约校验、提示词"压缩目录"（每类6条×180字符）

### DeepSeek Harness
- 旧四点（循环最小/事件驱动/契约先行/可恢复）成立 ✅
- ✅ 新增：事件三分域（会话=事实日志/agent=实时通道/tools=策略管道）+ 四派发模式（瀑布/串行/并行/即发即忘）
- ✅ 新增：Agent Notes 制度（505条决策记录、变更必附文档、feature→mechanism map 防核心膨胀、简化纪律48条）
- ✅ 新增：目标域自己拥有持久事件（goal/change 独立于 inbox）+ after-call 压力策略 + 路由感知压缩阈值

### Claude Code
- 仓库已是"契约仓库"（主程序编译二进制，源码=插件+文档+CHANGELOG）
- ✅ 扩展点6个：斜杠命令/子代理/技能/钩子/MCP/权限——全是 frontmatter 文件契约
- ✅ 钩子9事件：PreToolUse/PostToolUse/UserPromptSubmit/Stop/SubagentStop/SessionStart/End/PreCompact/Notification——能拦工具、拦退出、改入参、异步唤醒
- ✅ Ralph 插件：Stop 钩子拦截退出+状态文件+迭代数=显式"写→验→改"循环
- ✅ 验证闭环：deep-research 的 verifier 区分"未验证"vs"被证伪"

## 三、QRA 最终吸收清单（30 个设计 D1-D30）

### 记忆层（学 Hermes）
- D1 冻结快照：会话开始注入记忆，中途写盘不改变量提示词（保前缀缓存）
- D2 字符硬预算：每类记忆 ≤200字，满即报错逼模型当场合并（不写淘汰算法）
- D3 三档检索：热(全量注入) / 温(prefetch provider) / 冷(FTS5搜索)
- D4 后台审查 fork：每N个任务，fork 瘦 agent 重放日志提炼知识
- D5 永不真删：归档可恢复
- D6 apply_batch 原子批处理：一次调用完成腾位+新增

### 迭代层（学 prime-agent）
- D7 双评审门：小预算先问"该不该写"，大预算再问"写什么"
- D8 结构化最小编辑：create/update/delete + 每类知识固定归属
- D9 可执行契约硬校验：skill 必须带 reference+arguments 才让写
- D10 并发冲突拒绝：规划前快照，应用前重读比对
- D11 原子落盘 + 跨进程 mtime 同步
- D12 跨会话回滚：before/after 快照反向重放

### 架构层（学 DSH）
- D13 核心循环最小化：主流程只留取数→算信号→写报告
- D14 固定钩子：signal/pre-compute、report/pre-render 等瀑布钩子
- D15 事件三分域：事实日志(可重放) / 实时通道(可拦截) / 策略管道
- D16 能力接缝三角色：契约包/实现包/消费包分离
- D17 命名提供者注册表：多实现共存按名字挑
- D18 折叠投影恢复状态：状态=纯函数从日志折叠
- D19 模型可见⟺已记录不变式：每个结论可重算
- D20 feature→mechanism map：每个新功能声明挂哪个钩子

### 研究层（学 Claude Code）
- D21 一切皆文件契约：研报模板/验证清单=frontmatter md
- D22 描述即路由：技能/子代理靠 description+示例匹配
- D23 渐进式披露：元数据常驻/正文触发/参考按需
- D24 钩子把关：数据新鲜度门禁(PreToolUse block)+完成度验证(Stop block)
- D25 验证闭环：结论清单→独立核查子代理→验证不过不进报告
- D26 并行专业子代理+信心分：数据面/资金面/情绪面并行，>80分才采信
- D27 迭代循环控制面：写→验→改死循环+最大迭代逃生舱
- D28 状态外置到文件：中间结论/已核验事实落盘可断点续跑

### 制度层（学 DSH 的制度，最容易被忽略但最关键）
- D29 Agent Notes：每个变更附"决定+否决了什么+后果"
- D30 简化纪律：每季度主动删冗余，删除也文档化

## 五、核心认知（四源码共识）

1. **专业不来自模型变聪明，来自流程被显式搭建**
2. **防御性工程**：所有系统都默认"模型会出错、文件会被搞坏"，用代码兜底不赌自觉
3. **状态有边界**：前缀缓存/上下文大小/记忆容量，全是显式管理的预算
4. **删除权=创新权**：敢删才长得快（DSH 48条简化决策、Hermes 归档制）
5. **制度是架构的一部分**：设计文档制度（DSH）、评审门制度（prime）和代码同样重要
