# 机理研究：prime 源码深挖 + dsh 接插件思想评估（2026-08-16）

> 结论前置：prime 的持久内核**可以迁移，且已迁移**——它的核心创意不在代码技巧，在
> 「状态快照 × 恢复契约 × 模型自觉」三层协议；dsh 的「一切接插件」思想**照搬不可取，
> 精华已提取**——QRA 的 hermes 插件体系是「借底座」而非「造框架」，差距在 4 个工程
> 纪律不在机制。本档是两份源码研究报告（prime-agent / deepseek-harness）的事实合订本。

## 一、prime-agent 源码深挖

仓库：github.com/PrimeIntellect-ai/prime-agent（2026-08-15 阅读，packages/coding-agent/src/core/kernel/）
语言：TypeScript；内核协议：**手写 raw ZMQ（不用 jupyter_client）**——因为它在 Node 侧，无 Python 进程可借。

### 1.1 架构事实

- **每会话一个内核**；Linux 用 forkserver、macOS 降级 C（QRA 是纯 Python 宿主，直接用 jupyter_client，两条都跳过）。
- **restart() 是死代码**——prime 不做内核自动重启；死亡=报错。QRA 的自动重启+快照复活是增强（无人值守长任务刚需），不是背叛。
- **无执行超时**（只挂 AbortSignal）；无沙箱（README 明示 "not a security sandbox"）。QRA 保留 60s 超时+interrupt，理由见 D007。
- **工作流函数全是模型自建**：run_probe / apply_edits / run_trial / valcurve / mk / p_map 全部是模型在内核里写的函数，harness 一个都不内置。**这是「单工具哲学」成功的真正原因**：空间给足，模型自己长出工具面。实证：DeepSeek V4 Pro 26 小时连续运行，1229 次工具调用全部走 ipython，零重启。
- **rlm() 递归子代理 + comm 桥**：内核↔子代理消息桥接，analysis-only 合约（只读顾问）。属 P3 评估项，不迁。

### 1.2 可直接迁移的机制（A 级，已落地 qra_python）

| # | prime 机制 | 迁移状态 |
|---|---|---|
| 1 | 逐变量 dill.dumps 快照（单变量失败跳过，不炸全量） | ✅ 已迁：`_SNAPSHOT_TPL` 逐名 dump，失败进 skipped |
| 2 | 256MiB 快照上限 + tmp 写 + os.replace 原子替换 | ✅ 已迁：`MAX_SNAPSHOT_BYTES`（env 可调）+ tmp+replace |
| 3 | **快照时过滤**（垃圾名从不进 payload） | ✅ 已迁：快照模板内过滤（_ 前缀 + skip 名单含 In/Out/get_ipython/open/display/dill） |
| 4 | marker-line 结果协议（stdout 特殊标记行，防用户 print 撞车） | ✅ 已迁：`__QRA_KERNEL_STATE__` / `__QRA_KERNEL_RESTORE__` + JSON，取最后一次出现 |
| 5 | `import builtins as _b` 防遮蔽（用户把 open/print 遮蔽也不破坏快照路径） | ✅ 已迁：快照/恢复模板全程 _b.open/_b.print/_b.globals |
| 6 | 恢复顺序契约（restore 先于一切）+ 逐名容错 | ✅ 已迁：restore 逐名 loads，失败进 failed 名单继续 |
| 7 | restored/failed 名单注入模型上下文（模型知道什么复活了、什么要重建） | ✅ 已迁：复活 note 如实报告（含失败名单截断） |
| 8 | JSON manifest 伴生文件（快照内容可审计） | ✅ 已迁：`{sid}.json` 伴生 manifest |
| 9 | dispose 前最终 flush（有上限，不卡退出） | ✅ 已迁：atexit `_shutdown_all`，快照 5s 上限，失败用旧副本兜底 |
| 10 | busy-interrupt 重发（500ms×5s 宽限，耗尽判死走重启） | ✅ 已迁：`INTERRUPT_DRAIN_S` + `REINTERRUPT_INTERVAL_S` |
| 11 | allow_stdin=false（input() 直接抛错不悬等） | ✅ 已迁：`kc.execute(code, allow_stdin=False)` |
| 12 | NO_COLOR 内核环境（源头减 ANSI） | ✅ 已迁：kernelspec env |

### 1.3 改造迁移（B 级，QRA 按需变形）

- **死内核 poll 检测**：prime 无此需求（短交互）；QRA 长任务 → `_kernel_alive` 前置拦截 + 执行中每 5s 探活 + 重启重试一次（重启后自动快照复活）。
- **快照 debounce 参数不同**：prime 1500ms、无最小间隔；QRA 15s+30s——量化内核常驻大 DataFrame/回测状态，每笔执行都序列化会拖死内核。代价是崩溃丢失窗口 ≤45s，dispose 最终 flush 把窗口收敛到 ≈0。
- **输出截断不同**：prime 65536 字符；QRA 4000（env 可调）——hermes 消息语境下模型上下文经济优先。

### 1.4 不迁移（C 级）

raw ZMQ 协议（Python 侧有 jupyter_client）；forkserver（macOS 不可用）；rlm 递归子代理+comm 桥（P3 再评估）；内核沙箱（prime 自己都没做，QRA 已有 terminal/execute_code 同权工具，风险已记录）。

## 二、dsh「一切接插件」思想评估

仓库：github.com/deepseek-ai/deepseek-harness；本地装于 /opt/homebrew/lib/node_modules/@deepseek-ai/dsh/。
架构：cordis 元框架——插件系统为单一抽象，harness 自身就是插件联邦。

### 2.1 五个精华（值得吸收，标注成本）

| # | 精华 | 本质 | QRA 现状 | 成本 |
|---|---|---|---|---|
| 1 | **fail-loud 启动自检**：启动即验证插件间契约，坏就炸，不带着坏插件运行 | 契约前置 | 无 | 立即（半天）：qra_refine 启动自检 + 运行时依赖守卫 |
| 2 | **config-as-registry**：插件由 cordis.yml 入口表声明，零目录扫描 | 注册表=配置 | hermes 扫描 .hermes/plugins/<name>/__init__.py，已是约定优于配置 | 无需动 |
| 3 | **声明式 profile manifest**：插件声明自己提供什么、需要什么 | 依赖图可查 | hermes 插件只有 register(ctx) 无声明 | 中期（1-2 天）：QRA 插件 manifest 简版 |
| 4 | **差分热重载**：改配置只重启受影响插件，失败自动回滚 | 变更最小化 | hermes 无热重载 | 中期：仅配置文件级（不做插件级） |
| 5 | **配置 schema 硬校验**：非法配置启动即拒 | 类型前置 | 无 | 立即（半天） |

### 2.2 五个不照搬（含理由）

1. **cordis 框架本身**——QRA 是「借底座」（hermes 插件体系），再造一个元框架是重复造轮子且违 D002 精神。
2. **npm 分发形态**——QRA 是 Python 单仓，无跨机分发需求。
3. **配置写回（config writeback）**——配置文件是源码，程序写回破坏审计与版本控制。
4. **!js 表达式**——配置里嵌代码是安全面+可维护性双亏，QRA 零需求。
5. **多 profile 抽象（多环境切换）**——QRA 单环境，过度设计。

### 2.3 总评

QRA 对 dsh 的吸收形态是「借底座」：hermes 的 plugin registry + config.yaml enabled 列表就是
简化版 cordis。**机制上已经吸收好，真正的差距是 4 个工程纪律**（启动自检/依赖守卫/manifest/
schema 校验）——都进 P1 清单，不阻塞 P2。
