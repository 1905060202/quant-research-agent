# 机理研究：Prime 的 ipython 设计与 Claude Code 逆向设计（2026-08-14）

> 三路并行研究：A 拆解本机 prime-agent v0.7.2 一手源码（`/opt/homebrew/lib/node_modules/prime-agent/`，真实会话 jsonl）；B 核实 CC 泄露事件并检索社区逆向成果（附 URL）；C 摸清 hermes vendor 显示层与扩展点（file:line）。
> 结论先行：**Prime 的 CoT 全展示机理几乎全部可移植，hermes 数据链已完备、只差显示层，零 vendor 改动即可实现（D002 保得住）；CC 逆向里最值得嫁接的是事件化 Hooks 与 JSONL 双轨审计。** 改动方案见 ADR D007。

## 一、Prime：ipython 般设计与 CoT 全展示机理

### 1.1 单工具哲学（"天才感"的第一来源）

prime 的 `createAllToolDefinitions`（`dist/core/tools/index.js:24-28`）**只注册一个工具：`ipython`**，schema 仅一个 `code` 字段。bash.js/edit.js 存在但未注册（仅旧会话 replay 用）。本机真实会话 20 个 toolCall 全部 `name:"ipython"`。

含义：模型没有"查文件工具""跑 shell 工具"，想干任何事都得写 Python——**代码即工具编排**。官方 README 原话："persistent IPython is the built-in model tool; file operations, shell commands, tool use, subagents, and context management happen through code"。单工具带来：极简工具 schema（省上下文）、能力无上限（模型自组合）、但弱化确定性审计。

### 1.2 持久内核三层机理

1. **每会话一个真实 Jupyter 内核**：`KernelManager`（`dist/core/kernel/index.js:321`）不依赖 jupyter_client，**自实现 Jupyter 内核协议**——手工 HMAC 签名（`:166-196`）、ZeroMQ shell/iopub/control 三通道、`executionQueue=Promise.resolve()` 串行化。反向桥 `HOST_COMM_TARGET="host.request"`（`:42`）：内核里的代码通过 comm 向 TS host 发 typed request（文件操作/bash/子代理），host 执行后回传——**内核是模型面的控制环境，宿主操作必须走 TS 层**（安全边界在此）。
2. **dill 状态快照**（`state-snapshot.js`）：关闭/防抖时把用户命名空间序列化到 `session-artifacts/<id>/kernel-state.dill`；不可序列化对象（socket/GPU tensor）跳过并报告；模块按引用 pickle 恢复时重 import。这就是"变量跨轮存活、resume 后复活"的机理。
3. **forkserver**（`fork-server.js`）：Linux 下每 (python,cwd,env) 一个已 import 完的模板进程，新内核 fork 到 connection file，避免 ipykernel 冷启动（macOS 默认关闭）。内核 venv：`~/.prime/agent/kernel-venv`（Python 3.11 + ipykernel + dill）。

### 1.3 CoT 全展示数据流（核心机理）

```
provider SSE 流 → pi-ai 解析层 → thinking_delta 事件 → TUI 渲染 → jsonl 落盘
```

- **归一化**（`pi-ai/dist/providers/openai-completions.js:235-258`）：逐 delta 检查 `reasoningFields = ["reasoning_content","reasoning","reasoning_text"]`，取**第一个非空**（防 chutes.ai 双字段重复），accumulate 成 thinking block，`stream.push({type:"thinking_delta"})`。`thinkingSignature` 记录来源字段名（可溯源）。
- **回填**（`:670-726`）：thinking 回填进 `assistantMsg.reasoning_content`——**DeepSeek 多轮对话必须**（否则下一轮模型看不到自己上一轮的思考）。
- **一等公民**：thinking 不是独立事件类型，是 message 的 content block，**全量落盘可回放**。真实事件样例（本机 2026-08-13 会话，deepseek-v4-flash）：

```json
{"type":"message","id":"3ad93256","parentId":"0e44f2eb",
 "message":{"role":"assistant","content":[
   {"type":"thinking","thinking":"The user is asking in Chinese...","thinkingSignature":"reasoning_content"},
   {"type":"toolCall","name":"ipython","arguments":{"code":"import os, subprocess..."}}],
  "api":"openai-completions","provider":"deepseek",
  "usage":{"input":8309,"output":361,...},"stopReason":"toolUse"}}
```

- **渲染默认全展开**（`interactive-mode.js:604 hideThinkingBlock=false`），Ctrl+T 折叠。折叠态一行 recap：`thinkingRecap()`（`assistant-message.js:52`）取推理里**最后一个 `**加粗标题**`** 做摘要（推理摘要通常按段落标题组织）。thinking 用独立暗色 markdown theme（heading/code/quote 全染 `thinkingText` 色）+ 6 档 thinking level 边框色。

### 1.4 实时性机理（pi-tui）

- 每 token 一次 `updateContent()`（`message_update` case → `ensureAssistantStreamingComponent().updateContent()`）
- **一帧最多 reconcile 一次**：块结构不变则原地更新文本，保留每个 Markdown 子组件的 `VersionedRenderCache`（pi-tui render-cache.js）——逐字流式低延迟的关键
- 组件树：header（logo+快捷键）→ 对话流（user-message → assistant-message[text/thinking + tool-execution] → ipython-cell）→ footer。ipython-cell：代码 `›` gutter、输出同列缩进、显示 durationMs/error/stdout/stderr/diffs、pending 态 pulse 动画。主题 40+ token。
- **成本默认隐藏是品牌选择**（footer.js:32 "intentionally empty in the prime brand TUI"，`/usage` 才显示）——量化场景应反着来：显示成本。

### 1.5 daemon 与会话

- jsonl v3 头 `{"type":"session","version":3,...}`；事件=message + agent_status + 控制事件（parentId 树）
- resume：worker 重放 jsonl 重建组件树 + dill 恢复内核命名空间
- daemon：supervisor（路由/attach/健康）+ catalog（扫描归档）+ 每 root 树一个 resident worker；租约锁按 jsonl 路径；**关 TUI 不断 worker**（后台继续跑）
- 记忆：读 AGENTS.md/CLAUDE.md；`harness_state.json` 四类条目（prompt/memory/skill/subagent）+ `/refine` 自改；skills 遵循 Agent Skills 标准（SKILL.md 递归发现）

### 1.6 叙事澄清

"IPython moment" **不是官方用语**（本地 README/CHANGELOG 无此说法，社区叫法）。官方叙事=README 上那句"persistent IPython is the built-in model tool"。2026-08-05 MIT 开源。面试引用时注意用词。

## 二、Claude Code 逆向事件与九维设计

### 2.1 事件核实（说法要修正）

**准确说法：打包配置失误泄露 sourcemap，不是"发出明文打包"。** 美东 2026-03-31 凌晨 4:23，安全研究员 Chaofan Shou（@Fried_rice）发现 npm 包 `@anthropic-ai/claude-code` **v2.1.88** 的 `cli.js.map`（59.8MB）未被剔除，其 `sourcesContent` 字段内嵌**完整未混淆 TypeScript 源码**（约 1902 文件 / 51.3 万行）。根因：Bun 构建默认产出 sourcemap，`.npmignore` 没剔除。Anthropic 承认人为失误、下架旧版、请求移除 8000+ 转发仓库。**这是第二次同类失误**（2025-02 preview 版曾漏过同样的 map）。

泄露后加固：当前 v2.1.232 已改造成 7 文件"安装壳"（postinstall 拉取平台包，内含 292MB Mach-O 的 Bun SEA 二进制），strings 抽样只能拿到工具名/钩子事件/环境变量清单，无源码。

### 2.3 九维设计清单

1. **主循环**：核心 query.ts 约 785KB，被概括为"30 行 while(true) + 1800 行错误恢复 + 7 个 continue 站点"：组装消息→流式调 API→看 `stop_reason`（tool_use 则执行工具续循环，end_turn 返回）。逆向共识：**壁垒是 12 层渐进式工程包装，不是单点技术**。
2. **系统提示词工程**（最惊艳）：主 prompt 约 8500 token，**动态分段组装**——`systemPromptSection()`（可缓存段）+ `DANGEROUS_uncachedSystemPromptSection()`（会话特定段），一条 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 分界**省约 90% token 费用**（缓存读取仅 10% 成本）。注入顺序：主 prompt → getUserContext()（CLAUDE.md+日期）→ getSystemContext()（git 状态）→ 约 40 个条件 system-reminder。工具描述有 token 预算（Write~2100 / Bash~1800 / Read~900）。
3. **工具设计**：40+ 工具；**读工具并行、写工具串行**的分区调度；ToolSearch 延迟装载大工具集省上下文；Edit 约束=精确 `old_string` 唯一匹配；Bash 最重——`bashPermissions.ts` 单文件 2600 行，tree-sitter 解析 AST 防嵌套注入、剥离环境变量前缀、23 项安全检查。
4. **Subagent**：Task/Agent 工具；**fork 机制克隆父进程完整对话上下文**，禁止递归 fork；子代理用精简专用 prompt（Explore 575 / Plan 715 / general-purpose 285 / security-review 2521 token）；worktree 隔离；跨代理 Mailbox/Coordinator 模式。
5. **Hooks**：11 种事件（PreToolUse/PostToolUse/PermissionRequest/UserPromptSubmit/SubagentStop/Stop/Notification/SessionStart/SessionEnd/PreCompact/TodoWrite）；matcher 正则；stdin 注入 JSON（session_id/transcript_path/permission_mode/tool_input）；**exit 2=阻断且 stderr 直接喂给模型**；`permissionDecision` 可 allow/deny/ask 并改写输入；外部进程零上下文成本。
6. **记忆体系**：四级 CLAUDE.md（managed policy → 用户 → 项目 → AGENTS.md），`@import` 拆分；compact 用 autoCompact + 微压缩（陈旧工具结果做**零 API 调用的本地摘要**）。
7. **权限系统**：**deny > ask > allow，未匹配默认拒绝（fail-closed）**；7 种权限模式；权限引擎代码量约为主循环 3 倍，**判定独立于模型**（切断模型与宿主执行权的直连）。dontAsk 语义="别问直接拒"。
8. **会话持久化**：`~/.claude/projects/<hash>/<session>.jsonl` 全量 transcript + history/parent-transcript/trace 多轨；`--resume/--continue` 恢复。
9. **输出体验**：React+Ink 自研终端渲染（REPL.tsx 5000+ 行）+ diff 展示 + token/成本统计；`--output-format json/stream-json` 供流水线消费（流式 JSON 含子代理 `parent_tool_use_id`）。

## 三、hermes 底座现状（C 路：我们有什么、缺什么）

### 3.1 thinking 数据链已完备，只差显示层

- Anthropic Messages 流：`content_block_delta` 的 `thinking_delta` → `agent._fire_reasoning_delta`（`chat_completion_helpers.py:3995`）；**DeepSeek 走 anthropic 兼容端点时原样到达此分支**。
- OpenAI 兼容流（DeepSeek 原生路径）：`delta.reasoning_content` 累积 → 同函数（`:3559/3703`）。
- 汇合点 `_fire_reasoning_delta`（`run_agent.py:6604`）→ `reasoning_callback` + 可选插件钩子。文本 delta 走 `_fire_stream_delta`（`run_agent.py:~6552`），think 标签经有状态 scrubber 剥离——**正文与 CoT 天然分离**。
- 落盘：messages 表含 `reasoning/reasoning_content/reasoning_details` 三列（`hermes_state_common.py:318`）——CoT 完整持久化。
- **现状痛点**：`-z` 单发（`oneshot.py:290`）只 `real_stdout.write(final_response)`，thinking 全被丢弃；classic REPL 只有 5 行截断预览 + spinner。

### 3.2 扩展点（零 vendor 改动的 TUI 路径确证）

- `AIAgent` 构造回调 15+（`run_agent.py:432-520`）：tool_start/complete/progress、thinking、reasoning、clarify（阻塞桥）、stream_delta、interim_assistant、notice、event_callback 等。
- `run_conversation(stream_callback=...)` 参数（`run_agent.py:8017-8026`）。
- **官方先例 = oneshot.py 自己**：`from run_agent import AIAgent`（`oneshot.py:333`）程序化构造。三个生产前端（REPL/oneshot/tui_gateway）全部同模式驱动。
- `init_agent()` 显式 `__all__`（`agent_init.py:2924`）；SessionDB 可 `get_messages` 实现续聊；`--resume/-r` 已有。
- **语义陷阱**：`thinking_callback` 只是起止信号（spinner 文本），CoT 正文走 `reasoning_callback`，勿混用；`stream_delta_callback(None)` 是回合内流结束信号，必须处理；回调来自工作线程，TUI 端需线程安全入队；需 `quiet_mode=True + suppress_status_output=True` 防 `_vprint` 污染。

### 3.3 决策（详见 ADR D007）

- **路径 1（采用）**：导入 AIAgent 自建循环（照抄 oneshot 最小参数集），注入自有回调，显示层 100% 接管——零 vendor 改动。
- 路径 2（否决）：骑现有 `hermes --tui`——协议无公开 schema，属私有接口，且定制 UI 会碰 vendor。
- 路径 3（否决）：改 cli.py 截断逻辑——违反 D002，且路径 1 已覆盖。

## 四、对 QRA 的移植清单

### 4.1 采纳（Phase 1-3，见 ADR D007）

| # | 来源 | 设计 | 落地形态 | 成本 |
|---|---|---|---|---|
| 1 | prime | CoT 全展开实时渲染 + Ctrl+T 折叠 recap（最后加粗标题） | qra_console（Rich Live） | 低 |
| 2 | prime | 逐 token 流式 + 回合结束信号处理 + thinking 暗色主题 | qra_console | 低 |
| 3 | prime | usage/成本嵌消息（量化场景**显示**而非隐藏） | qra_console footer | 低 |
| 4 | prime | 持久内核工具：代码即工具、变量跨轮存活、dill 快照 | qra_python 插件（jupyter_client+ipykernel） | 中 |
| 5 | prime/CC | 会话可回放（jsonl/state.db 双轨 + resume） | Phase 3 | 低-中 |
| 6 | CC | Hooks 事件化（PreToolUse/PostToolUse 正则 matcher + stdin JSON + exit 2 阻断喂模型） | qra_hooks 插件（基于 hermes plugin stream hooks） | 中 |
| 7 | CC | 工具描述 token 预算意识（QRA 工具 schema 精炼） | 现有插件 schema 复审 | 低 |

### 4.2 不采纳（理由）

| 设计 | 不采纳理由 |
|---|---|
| prime 单工具哲学（唯一 ipython 工具） | QRA 的结构化工具（行情/信号/检索）有确定性、可验证、可审计优势；bench 机械评分与 qra_verify 确定性检查器全建立在其上。**内核工具做加法，不做替换**。 |
| CC 提示词分段缓存（DYNAMIC_BOUNDARY） | 需要动 hermes 组装逻辑 = vendor 改动，违反 D002；收益（省 token）可在 provider 层配置缓存策略部分补偿。 |
| CC Bash AST 安全检查（2600 行） | QRA 工具是结构化 schema（非 bash）；若未来加 bash 类工具再评估。 |
| CC 权限引擎重写（fail-closed 规则引擎） | hermes 已有审批体系（approval gates + review fork），重写=负 ROI。 |
| prime daemon 进程拓扑（supervisor/catalog/worker） | QRA 单机单用户场景无后台 agent 常驻需求；需要时再评估。 |
| CC autoCompact 微压缩 | 依赖 Claude 专有 API 特性；hermes 侧可用记忆 provider 近似，优先级低。 |

## 五、风险与验证计划

- **回调线程安全**：回调来自工作线程，console 端所有渲染状态必须经队列/锁，先写单测打线程竞态。
- **`init_agent` 参数漂移**：pin 17d6a7d，照抄 oneshot 最小参数集，升级时回归。
- **不要复制 oneshot 的 `os._exit`**（`main.py:176` 链）：自建循环用正常 finally 清理。
- **验证铁律**：qra_console 端到端（真实 API 三次运行：CoT 全展示、折叠 recap、工具调用块）；qra_python 四级验证（内核执行→变量跨轮存活→dill 恢复→bench 题）；jsonl 双轨抽查。
