# 🔬 系统化深度研究方法论 v2.0

## 核心原则

### 原则 -1: 先思考，再采集（🆕 v2.0）
**外部信息验证你的思考，而非替代你的思考。**

在接触任何外部源之前，先从自己的知识、经验和第一性原理出发：
1. 回答"这个问题的核心是什么？"
2. 形成独立的分析框架和假设
3. 写下"如果我必须不看任何外部信息就回答，我会说什么"

然后外部信息的作用是：
- 验证你的假设（对了还是错了？）
- 提供你不可能凭空知道的具体数据（价格、日期、数字）
- 修正你的推理链条（哪一步的假设错了？）

**反例**: GTA 6 研究 v1.0-v4.5 全部是"先采集，再综合"。即使推理也基于外部信息的排列组合。用户反馈："你的思考、推理、创意才是我想看到的。"

### 原则0: 研究≠检索
信息检索是工具，推理演绎才是价值。[[feedback_research_detective_not_librarian]]

### 原则1: 一手源铁律
权威数据（价格/日期/平台/规格）必须从官方一手源确认。[[feedback_research_primary_source_first]]

### 原则2: 证据账本（Evidence Ledger）
每条外部声明必须绑定到具体的源段落，追踪溯源路径。

### 原则3: 先广后深（Broad First, Deep Later）
穷举所有可能的物料源 → 再深入分析。

### 原则4: 探索与利用分离
信息收集和信息综合应该是不同的阶段，使用不同的策略。

### 原则5: 多流认知综合
从多个认知视角同时审视同一信息，然后综合。

## 执行流程: 7阶段深度研究管道（v2.0）

### 🔴 Phase -1: 独立原创思考（🆕 v2.0）

**在接触任何外部信息之前执行。**

**步骤**:
1. 问自己"这个问题的核心到底是什么？"——不要复述问题，要找到其本质
2. 从第一性原理出发："关于这个领域，最基本的真理是什么？"
3. 形成假设框架："如果我是这个产品的设计者/这个决策的制定者，我会怎么做？为什么？"
4. 写下核心论点——一组独立的、原创的判断
5. 标注"我知道的"vs"我不确定需要外部验证的"

**输出**: 一份纯原创的分析草稿（零外部引用），包含：
- 核心框架（如"GTA 6在解决的三个问题"）
- 独立判断（如"恋爱关系是唯一能让背叛产生真正伤害的类型"）
- 担忧和批评（如"变现结构扭曲设计动机"）
- 思想实验（如"如果我是设计师，我会..."）

**然后在 Phase 0-5 中，用外部信息验证和修正这些思考。**

### Phase 0: Frame — 穷举数据源
（原 Phase 0 + Phase 0a 时间线穷举 + Phase 0b 完整性自检）

### Phase 1-6: 采集→提取→验证→推理→综合→回顾
（保持 v1.2 版本不变）

**目标**: 在开始任何搜索之前，先建立完整的数据源地图。

**步骤**:
1. 识别所有官方一手源（官网/商店/财报/新闻稿/专利/招聘页面）
2. 识别所有高价值二手源（权威媒体/社区/分析师）
3. 识别所有推理维度（技术/商业/叙事/战略）
4. 对每个源标注优先级和采集方式（WebFetch/WebSearch/直接访问）

**输出**: 数据源清单 + 采集计划

**GTA 6 反例**: 63张截图(6.24发布)在6.25预购日被广泛报道，但首版研究完全没有采集。如果在Phase 0就穷举了"Rockstar官方渠道所有物料"，就不会遗漏。

### Phase 1: 采集（Collect）— 先广后深

**策略**: 两轮采集

**第一轮: 广撒网（Broad Sweep）**
- 基于数据源清单，对所有源进行第一轮WebFetch
- 目标: 确认哪些源有信息、信息量多少、是否需要第二轮深入
- 不对信息做深度分析，只建立"信息地图"
- 工具: 并行WebFetch + 快速扫描

**第二轮: 深挖（Deep Dive）**
- 对第一轮确认有丰富信息的源进行完整提取
- 使用结构化提取（提取所有声明、所有数据点、所有可验证的事实）
- 工具: WebFetch with detailed prompts + 专项WebSearch

**GTA 6 反例**: 第一版只做了一轮搜索就直接写文档，没有"先确认信息全貌"的阶段。

### Phase 2: 提取（Extract）— 声明化

**目标**: 将非结构化的源内容转化为结构化的可验证声明。

**声明格式**:
```
声明ID: C-001
内容: "GTA 6标准版售价$79.99"
来源: PlayStation Store https://www.playstation.com/en-us/games/grand-theft-auto-vi/
来源类型: 🟢 官方一手
提取时间: 2026-07-05
重要性: central | supporting | contextual
```

**关键**: 区分"源说了什么"和"源暗示了什么"。前者是声明，后者是推理（应该在Phase 4处理）。

来源: NIST Open Deep Research的"faithfulness/completeness/sufficiency"三维评估框架

### Phase 3: 验证（Verify）— 对抗性多层核查

**三层验证体系**:

**L1: 源质量评分**
- 🟢 官方一手: Rockstar官网/PS Store/财报/Business Wire
- 🟡 权威二手: IGN/Digital Foundry/GameSpot（知名媒体）
- 🟠 中等二手: 社区项目/零售商泄露/知名leaker
- 🔵 低质量: blog/论坛/匿名来源

**L2: 3-投票对抗性验证（已有，来自deep-research工作流）**
- 每条核心声明由3个独立验证者核查
- ≥2/3否决 → 声明被移除
- 关键改进: 验证者必须**追溯到一手源**，不能只看二手汇总

**L3: 交叉验证矩阵**
- 同一个事实是否被多个**独立**来源确认？
- 注意: 来源独立 ≠ 来源不同。如果源A和源B都在引用同一个一手源，它们不是独立的。

来源: DuMate-DeepResearch的rubric-based验证, AutoVerifier的6层验证, NIST的evaluation probes

### Phase 4: 推理（Reason）— 多流认知综合

这是本方法论的核心创新——从"信息聚合"到"推理演绎"的跨越。

**多流认知框架**（改编自Observer框架）:

对每个关键主题，从5个认知视角同时审视：

| 视角 | 问题 | 产出 |
|------|------|------|
| **分析** | 这些事实之间的联系是什么？有什么模式？ | 因果链、逻辑推理 |
| **批判** | 这里有什么矛盾？有什么被遗漏？有什么可能被误解？ | 潜在错误、信息缺口 |
| **创造** | 基于这些事实，可以想象出什么新可能性？ | 推演、假设、预测 |
| **系统** | 各部分如何组成一个整体？系统层面的影响是什么？ | 架构图、系统动力学 |
| **实用** | 这对用户/玩家/读者意味着什么？他们关心什么？ | 影响评估、实际意义 |

**实施方式**:
- 对复杂主题，可以并行启动5个thinking代理，每个从一个视角分析
- 对简单主题，在脑中过一遍5个视角即可
- 关键: 5个视角的产出需要**综合**——不能只是5份独立报告

**推理标注体系**:
```
🟢 事实: 多个一手源直接确认
🟡 强推理: 单一事实链 + 高置信度
🟠 中推理: 多事实链 + 中等置信度
🔵 弱推理: 推测/想象，基于有限证据
🔴 已证伪: 经验证被否决
```

来源: Observer框架 (Zenodo), Framework of Thoughts (arXiv 2602.16512)

### Phase 5: 综合（Synthesize）— 结构化输出

**合成策略**:

1. **主题聚合**: 将相关声明和推理按主题聚合（不是按来源）
2. **叙事构建**: 围绕核心发现构建叙事弧线（不是信息清单）
3. **层级化**: 核心发现 → 支撑细节 → 背景上下文
4. **可视化**: 使用表格/流程图/时间线增强理解
5. **间隙标注**: 明确标注"我们还不知道什么"

**输出检查清单**（来自GTA 6教训）:
- [ ] 所有权威数据追溯到一手源
- [ ] 每条推理标注了置信度和推理链
- [ ] 区分了"源说了什么"和"我推理了什么"
- [ ] 标注了信息缺口和不确定性
- [ ] 用户可以轻松找到任何事实的溯源路径
- [ ] 文档长度和深度匹配了用户的需求层次

### Phase 6: 回顾（Reflect）— 方法论自我改进

**任务结束后**:
1. 过程中哪些环节出了问题？（如定价错误、物料遗漏）
2. 根本原因是什么？（如没做Phase 0穷举）
3. 方法论如何改进？（如加入"一手源优先确认"规则）
4. 写入记忆/方法论更新

来源: GEPA self-optimization (arXiv 2604.02988), AgentDisCo的policy bank

## 需求层次识别

在开始研究前，先判断用户的需求层次——决定了研究的深度和范围：

| 层次 | 用户要的是 | 方法 | 典型任务 |
|------|-----------|------|----------|
| **L1: 事实核查** | "这是真的吗？" | Phase 0-3 | 确认一个数据点、辟谣 |
| **L2: 信息汇总** | "关于X都知道什么？" | Phase 0-3 + Phase 5简化版 | 知识汇总、入门指南 |
| **L3: 分析推理** | "这意味着什么？" | 完整6阶段 | 投资分析、技术评估 |
| **L4: 侦探拼图** | "拼凑出完整的图景" | 完整6阶段 + 多流认知 | GTA 6全维度研究、竞争情报 |

**GTA 6 教训**: 用户要的是L4（侦探拼图），我第一版给的是L2（信息汇总）。层次错配是根本问题。

## Claude Code 具体实施指南

### 何时使用动态工作流（Workflow工具）

适合: 大规模并行搜索（Phase 1）、对抗性验证（Phase 3）、多流认知（Phase 4）
不适合: 简单事实确认、单一来源深度阅读

### 何时使用Agent工具

- Explore agent: 广撒网搜索（"搜索关于X的所有信息"）
- General-purpose agent: 深度阅读单个来源并提取结构化声明
- Plan agent: Phase 0设计数据源清单和研究计划

### 工具选择决策树

```
需要查官方价格/日期? → WebFetch一手源（不用WebSearch）
需要广撒网找信息? → 并行WebSearch
需要深度阅读一个页面? → WebFetch with detailed prompt
需要验证一个声明? → Agent (general-purpose) × 3 + 对抗性验证
需要多流推理? → 5个thinking agent并行（或Workflow pipeline）
需要写长文档? → 本地Write，不要依赖agent输出
```

### 研究系统提示词（可设为context别名）

```
你是Claude Code的研究模式。在开始任何研究任务前:
1. Phase 0: 先穷举所有可能的数据源
2. 权威数据必须从一手源确认
3. 区分"源说的"和"我推理的"
4. 每条推理标注置信度和推理链
5. 先判断需求层次（L1-L4），匹配合适的深度
```

## 版本历史

- v1.0 (2026-07-05): 初始版本。融合DuMate/AgentDisCo/GEPA/NIST/Anthropic等2025-2026年前沿方案，基于GTA 6研究任务复盘
- v1.1 (2026-07-05): 经Take-Two战略分析任务落地验证。确认Phase 0防止100%源遗漏。发现改进点：声明提取需结构化模板、高风险数字声明需自动触发一手源验证、Phase 4"创造"视角需外部启发注入。
- v1.2 (2026-07-05): 修补时间维度盲区（Phase 0a时间线穷举）+ 演绎触发框架（Phase 4按声明类型自动触发工程/物理反推）+ 完整性自检（Phase 0b）
- 🔴 v2.0 (2026-07-05): **根本性修补**。用户反馈"你的思考、推理、创意才是我想看到的"——所有v1.x版本本质上是外部信息聚合+推理标注，缺少从第一性原理出发的独立原创分析。加入 **Phase -1（独立原创思考）**：在任何外部信息采集之前，先从自己的知识、经验和第一性原理出发，形成独立的分析框架和核心观点。外部信息的作用是验证和修正，而非替代思考。

## 落地验证记录

**回测**: GTA 6 v1.0翻车现场 → 14/14高价值源遗漏(100%) → Phase 0将遗漏率降至0%
**实跑1**: Take-Two战略分析 → 15源预标识/0遗漏 → Phase 4产出12推理段落
